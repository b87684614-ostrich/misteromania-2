# 🕹 Мистеромания

Онлайн-игра: ты — **Сосуд**. Перед входом нужно пройти капчу **«нарисуй себя»** в Paint-окне,
затем сражаться с **мистерами** — побеждённый мистер присоединяется к твоей команде и воюет рядом.

## Как играть

1. Введи **никнейм** и выбери режим капчи:
   - ⏱ **Обычная** — 5 минут на рисунок, кнопка «О'кей» разблокируется только после таймера (время проверяет **сервер**);
   - 🎨 **Творчество** — без лимита времени, можно нажать «О'кей» когда дописал шедевр.
2. Нажми **«Я не робот»** → откроется Paint. Нарисуй себя (кто сидит в этой игре) → **О'кей**.
3. В игре: **WASD/стрелки** — движение, **мышь** — прицел, **клик/зажатие** — удар.
   Мистеры нападают толпой; объединяйся с другими сосудами онлайн. Команда — до 10 мистеров.

## Антижульничество капчи (на сервере)

- Время капчи отсчитывает **сервер** (сессия в SQLite), клиентский таймер можно подделать — сервер не пропустит.
- Сервер сам **декодирует PNG** рисунка и проверяет пиксели: долю «чернил», число цветов, размер файла.
- Проверяются и мазки клиента: минимум мазков, точек, длины линий, размера рисунка.
- Одна точка / одна линия / пустой холст / заливка всего холста → **отказ**, попытка сохраняется в БД.
- 3 провала подряд с одного IP → **бан на 10 минут**.
- Все рисунки (честные и жульнические) хранятся в базе данных → см. `/gallery`.

## Технологии

Node.js (≥ 22.13) + Express + Socket.IO (real-time) + **SQLite через встроенный `node:sqlite`**
— никаких нативных зависимостей, сборка на Render не компилирует C++-код.
Хранение: игроки, капча-сессии, рисунки (base64 PNG), токены входа, захваты мистеров, баны.

## Деплой на Render (бесплатно)

Сервис собирается как **Node.js** (`runtime: node` в `render.yaml`) — Docker не используется.

1. Залей проект на GitHub:
   ```bash
   git init && git add -A && git commit -m "Мистеромания"
   git remote add origin https://github.com/<твой-ник>/misteromania.git
   git push -u origin main
   ```
2. На [render.com](https://render.com) → **New + → Blueprint** → выбери репозиторий.
   Файл `render.yaml` уже в проекте — Render подхватит сервис `misteromania` автоматически.
3. Готово: игра будет доступна по адресу вида `https://misteromania.onrender.com`.

### Если в репозитории игра лежит в подпапке

Если ты запушил репозиторий, где файлы лежат внутри папки `misteromania/`
(в репо есть `misteromania/package.json`, а в корне — нет), то в `render.yaml`
уже прописано `rootDir: misteromania` — Render соберёт приложение из этой папки.

- **Вариант A:** запушь эту версию с `rootDir: misteromania` — деплой починится сам.
- **Вариант B:** перенеси всё содержимое папки `misteromania/` в корень репозитория
  и **удали** строку `rootDir:` из `render.yaml`.

### Траблшутинг: `npm error enoent Could not read package.json: /opt/render/project/src/package.json`

Это ровно та ошибка, когда `package.json` не в корне репозитория, а `npm install` выполняется
в `/opt/render/project/src`. Лечение — одно из двух:
- `rootDir: <имя-папки>` в `render.yaml` (уже выставлено: `misteromania`),
- либо перенос файлов игры в корень репозитория (и удаление `rootDir`).

После фикса нажми **Manual Deploy → Deploy latest commit** (или запушь новый коммит — сработает автодеплой).

> ⚠ На бесплатном тарифе Render диск эфемерный и сервис «засыпает» без запросов (первый запрос
> может задержаться до ~50 сек — это нормально, см. фиолетовую плашку на скрине). Чтобы база SQLite
> сохранялась между рестартами, добавь **Render Disk** (1 GB, mount path `/var/data`)
> и раскомментируй `DATA_DIR: /var/data` в `render.yaml`.

## API

- `POST /api/captcha/start` `{nickname, mode}` → `{sessionId, startedAt, serverNow, minMs}`
- `POST /api/captcha/ok` `{sessionId, nickname, strokes, image(dataURL PNG)}` → `{ok, token}`
- `GET /api/health`, `GET /api/stats`, `GET /gallery`
- Socket.IO: auth token → `welcome`, `state`, `ev`; клиент шлёт `input`.
